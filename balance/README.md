# 百战天元 · 平衡工具链（balance/）

数值深度平衡的脚手架真源：**四维分析（阵容 / 棋子 / 羁绊 / 装备）× CRN 配对统计 × 进程池并行 × SQLite 工件库**。2026-09-02 重建，取代 `scripts/sim*` 散装脚本族（旧 npm 命令名全部保留为别名，工作流不断层）。

```
balance/
  cli.ts                 统一入口：npm run balance -- <command>
  lib/                   框架核心（与命令解耦，测试直测）
    seeds.ts             CRN 种子表（唯一真源，公式金锁）
    patch.ts             数值补丁层（调参不改源码；journal 逆序还原）
    engine.ts            战斗执行原语（runPair / pairedItemsDelta）
    pool.ts + poolChild  fork 进程池（算力层）
    matrix.ts            配置矩阵聚合（winRate/极差/位置公平 + 逐单位统计）
    comps.ts             阵容装载器（预设 / 自定义 JSON，造价带校验）
    store.ts             SQLite 工件库（node:sqlite，零新依赖）
    report.ts            控制台报告渲染
    runctx.ts / args.ts  公共旗标解析
    comp-random.ts       随机阵容生成（先手公平检验用）
  commands/              命令层（matrix/sweep/ab/traits/items/units/trend/bench/selftest + 迁移专项）
  specs/                 扫描 spec（OAT 轴定义）
  out/                   工件输出（balance.db + 导出；gitignored）
```

## 命令速查

| 维度 | 命令 | 回答的问题 |
|---|---|---|
| 阵容 | `matrix [n]` | 九套预设（或 --comps 自定义）的综合胜率、极差、位置公平、超时率 |
| 阵容 | `sweep <spec> \| --set k=v` | 某参数动一动，断面怎么动（Δ/噪声带/边际斜率） |
| 阵容 | `ab --set k=v [--pairs 4]` | 这个改动把机关相关的克制边移动了多少（定向高精度） |
| 棋子 | `units [--sort dealt\|taken]` | 每颗棋子的场均伤害/承伤/类型构成/施法/生存率（随 matrix 入库） |
| 羁绊 | `traits [n]` | 每条羁绊的数值给它的阵容贡献多少胜率（scale=0 压制 vs 基线） |
| 装备 | `items [n]` | 单件边际、合成增益、同件堆叠递减、异件协同（logit 口径） |
| 趋势 | `trend [k]` | 跨版本断面移动（读库，按阵容名对齐） |
| 门禁 | `selftest` | 数据自检/确定性/CRN/进程池一致/先手公平（战役前必过） |
| 算力 | `bench [n] --scaling` | 单进程吞吐 + 进程池实测加速比 |

通用旗标：`--seed S`（默认 20260829，历史可比口径）`--workers W` / `--serial` `--comps <file.json>` `--no-save`。

## 标准工作流（调平衡的唯一路径）

```
balance selftest                     # 0. 门禁
balance matrix 120                   # 1. 断面基线（入库）
balance units                        # 2. 棋子维：找贡献异常者
balance traits                       # 3. 羁绊维：找贡献过高/过低的羁绊
balance ab --set <候选> --pairs <下标> # 4. 定向验证（CRN 配对，≥2p = 实质移动）
balance sweep --set <候选组合>        # 5. 组合快扫（极差 + 下限双指标）
（有效则写回 src/data 源码字面量）
balance matrix 200 --seed 20260902   # 6. 换种子复测防种子过拟合，入库
balance trend                        # 7. 对比历史断面
```

红线（沿用既定纪律）：反伤总量旋钮踩悬崖（非单调），护卫/反伤类改动必须全矩阵 CRN 复验；先正确性后平衡，正确性修复移动断面不算回归。

## 决策记录

### D1 · 算力层：fork 进程池，否决 GPU 移植（2026-09-02）

深度利用硬件的评估结论：

- **数据并行轴才是对的轴。** 平衡模拟的并行单位是「局与局独立」（一场战斗 ~200 tick 的分支密集事件流），不是「向量宽」。进程池把独立对局摊到全部物理核，已在该轴上饱和。
- **GPU 移植 = 第二套引擎 = 漂移。** 战斗内核是 TypeScript（技能/羁绊/装备钩子、闭包事件流），移植 WGSL compute shader 需要完全重写判定逻辑，从此每个机制改动都要双写同步——违反全项目「单一真源」纪律，正确性成本远超吞吐收益。
- **Node WebGPU 不可依赖。** 截至 Node 22 仍实验态，Windows 无头环境驱动可用性不稳定，工具链不能建立在它上面。
- **worker_threads 与 tsx 不兼容**（实测：`.ts` 无法加载），fork 子进程以 `['--import','tsx']` 独立加载（实测可用）。

实测（i9-14900HX，30 进程）：矩阵 8640 局 5.7s（单进程 630 局/s 折算 13.7s，短任务下 fork 启动开销占比高；作业越大加速比越接近核数，见 `bench --scaling`）。`runPool` 的作业协议是唯一接缝——未来若出现可隔离的数值核（如批量伤害表预计算），可在不改命令层的前提下挂 GPU runner。

**不挂起保证**：除每作业 120s 硬超时、作业中途子进程退出即整池失败外，fork→ready 的初始化阶段同样上钟（30s）——tsx 加载 / 启动异常卡死时父进程不会永远等 dispatch；`ab` 与 `sweep` 的 `--set` 覆盖路径在 fork 子进程前于父进程一次性 apply+reset 预检（键非空、值有限、路径存在），非法输入不耗算力即报错。

**可信度地基**：种子是纯函数、局间零共享，并行结果与串行逐位一致——由 `selftest` 第 4 关与 `tests/balance-tools.test.ts` 双断言看守。

### D2 · 存储：SQLite 工件库，游戏真源不动（2026-09-02）

- **是否用数据库存数值？——工具侧是，游戏侧否。**
- 工具侧：实验历史（runs / 配置 / 配对结果 / 逐单位统计 / 装备边际 / 羁绊贡献）全部进 `balance/out/balance.db`（`node:sqlite` 内置，**零新增 npm 依赖**）。跨版本趋势、单位排行、任意回溯复算从「翻一堆 JSON」变成一句查询；旧 JSON 工件仍可被 `sweep --compare <path>` 直读。
- 游戏侧：数值真源仍是 `src/data/*.ts` 常量字面量——编译进发布物、单文件离线可玩、类型受控。数据库**只进不出**：不存在任何「从 DB 读数回灌游戏」的代码路径（tests 断言 src/ 无 balance/ 引用）。把游戏数值搬进 DB 会破坏单文件发布形态与零依赖纪律，否决。

### D3 · 与游戏主体分离

- 依赖方向单向：`balance/ → src/（只读）`；`src/` 永不引用 `balance/`（测试看守）。
- 补丁只落在 fork 子进程的独立模块实例上，跑完即弃——扫描进程崩溃/泄漏不影响任何东西。
- `scripts/check-boundaries.mjs` 只检 `src/`；vite 构建不触 `balance/`；`tsconfig` 仅做类型检查（不进产物）。
- 代价声明：`balance` 工具需要 Node ≥ 22.5（`node:sqlite`）；游戏本体的 `engines` 自 2026-09-02 起统一为 `>=22.5`（与 `.nvmrc`/CI 同口径，见 root README）。

### D3 · 覆盖一律「注入」而非「改写真源」

shop 概率行覆盖采用注入口径：`rollShop` 接受可选 `table` 参数（缺省读取全局配置），`Match.shopTable` 供整局模拟挂载覆盖表；对局主路径保持默认读取，确定性契约与真源不变。工具层与补丁层遵循相同纪律：所有临时覆盖只作用于调用方显式持有的参数或子进程实例，源码字面量严格只读。

### D4 · 平衡方法论：相对平衡与百花齐放，不是绝对平均（2026-09-02 定稿）

**目标函数**（matrix/sweep 报告的「阵容带/边带」两行就是它的度量）：

1. **阵容带 [44, 58]**——每套构筑在同一造价带下胜率落带：下限保证「不是陷阱选择」，上限保证「不是自动赢」。带内的 52% vs 48% 差异是 meta 纹理，不是要消灭的误差。
2. **边带 [20, 80]**——消灭 0%/100% 绝对边。硬克制的健康形态是 70/30（counter 有回报但仍留能动性）；绝对边把对局变成掷硬币，是首要修治对象。
3. **极差是诊断量，不是目标**——岩纸布（互有克制）比「人人 52%」健康。压平一切会毁掉身份，历史上也从未做到过（六套时代 15.4% 已是断面性质的上限区）。

**身份保留清单**（调参红线：削强项不如开绝对边）：

| 构筑 | 身份 | 应强 | 应弱 |
|---|---|---|---|
| 护卫 | 反伤墙 | 近战rush（快攻） | 持续法术（法爆/幽冥） |
| 快攻 | 刺客斩杀 | 脆皮后排（法爆） | 墙与分摊（护卫/墨门） |
| 法爆 | 一发定胜负 | 聚怪无位移（机关） | 斩杀线以下被切（快攻）、复活（幽冥） |
| 幽冥 | 死了再战 | 打空爆发的对手（法爆） | 滚雪球（兵家） |
| 墨门 | 兼爱分摊 | 单点爆发 | 人海消耗（机关） |
| 机关 | 群海第4击 | 慢速大目标（墨门） | 瞬发清场（法爆/天庭） |
| 兵家 | 百战滚雪球 | 慢热阵容 | 成型墙（护卫） |
| 天庭 | 护盾法爆 | 依赖普攻的 | 内战爆发更高/压盾（兵家/幽冥） |
| 妖族 | 吸血化形 | 拉锯战 | 斩杀线压制 |

调参次序：先开绝对边（给被 0% 的一方一条活路）→ 再压带外阵容（护甲墙削续航不削身份）→ 最后才是均质化微调（基本不做）。

### D4 补记 · 边带的可达性边界（2026-09-02 定档证据）

规范帧（同造价/无装备/自动站位/确定性种子）下的 0%/100% 硬边对 OAT 数值旋钮
（护甲、破甲、续航、血量、暴击、全队光环全档）与双方同装试验均零响应 ——
是同构对局的结构判定。1.13.0 的四个条件化通道吃掉三条硬边并把极差 28.0→11.4；
残余硬边（幽冥→法爆、兵家→法爆、护卫→兵家、机关→墨门等 4~7 条随种子浮动）
按「结构性克制」管理：反制位在玩家能动性（侦查换站位/针对配装/经济压制），
后续收窄走 thornResist 式条件化通道逐边立项。工件证据：matrix run 边带清单 +
edge-probe / channel-tune 两次 OAT 扫描（balance/out/balance.db）。
