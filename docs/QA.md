# 百战天元 · QA 质量规范

本规范定义项目的质量门禁、测试边界和验收责任。目标不是增加测试数量，而是用最短、
可重复的证据链阻止真实缺陷进入主分支和发布包。

## 1. 基本原则

1. **风险驱动**：断言必须对应明确的玩家故障、资产损失、进度中断或发布失败。
2. **单一职责**：类型、行为、构建、平衡、资源和视觉由各自最合适的门禁负责。
3. **快速默认**：日常完整门禁保持在分钟内，开发者每次交付前都能运行。
4. **变更加严**：默认门禁之外，只追加与改动领域相关的专项验证。
5. **同构执行**：本地与 CI 使用同一个 `npm run qa`，不维护两套通过标准。
6. **失败透明**：不自动重试、不静默跳过、不靠更新快照消除未知差异。

项目不设覆盖率百分比目标。覆盖率不能代替风险分析，也不能证明 Canvas 画面、平衡结果或
发布包可用。

## 2. 质量分层

| 层级 | 入口 | 解决的问题 | 执行时机 |
|---|---|---|---|
| 静态正确性 | `npm run typecheck` | 类型错误、无效调用、未使用代码 | 每次改动 |
| 架构边界 | `npm run check:boundaries` | 七层（core/data/game/render/ui/audio/music）加 src 根组合文件（main/version）的越层依赖、浏览器 API 和非确定性随机源；覆盖计数断言保证新文件不脱检；未登记的顶层目录默认拒绝（要求显式登记层职责），game 层另禁 `performance.now` 与密码学随机 | 每次改动 |
| 核心行为 | `npm test` | 玩法、资产、存档、回放、输入是否破坏 | 每次改动 |
| 生产可构建 | `npm run build:app` | Vite 生产打包与资源解析是否成功 | 每次改动 |
| 默认 QA | `npm run qa` | 依次执行以上四层 | 交付前、CI |
| 领域专项 | 模拟、音乐审计、实机冒烟 | 平衡、授权资源、真实渲染与交互 | 按改动领域 |
| 发布验收 | `npm run release` | 依赖/资源审计、双形态产物、外链扫描与原子替换 | 发版时 |

`npm run build` 适合单独构建，内部包含类型检查；`npm run qa` 直接调用 `build:app`，避免同一轮
流程重复类型检查。

## 3. 标准流程

### 3.1 开发与交付

1. 判断改动影响的领域。
2. 开发过程中运行相关测试；需要持续反馈时使用 `npm run test:watch`。
3. 完成后运行 `npm run qa`。
4. 根据变更矩阵运行领域专项门禁。
5. 检查差异，确认没有 `.only`、跳过项、临时基准或生成物混入。

### 3.2 持续集成

GitHub Actions 在 Pull Request 和 `main` 分支推送时执行：

```text
npm ci
└─ npm run qa
   ├─ TypeScript strict
   ├─ Architecture boundaries
   ├─ Vitest core behavior
   └─ Vite production build
└─ npm run audit:deps     # 高危依赖在 PR 阶段暴露
└─ npm run audit:music    # 音乐清单/哈希/授权在 PR 阶段暴露
```

CI 追加两道发布门禁中最便宜的审计，让许可证、哈希漂移与高危依赖在合并前失败，
而不是积压到 `npm run release` 才爆炸。单文件形态构建、外链扫描与产物体检仍由发布
命令完整覆盖。同一分支的新提交会取消旧任务，门禁超时为 10 分钟。CI 失败时主分支和
发布流程均不应继续。

### 3.3 发布

`npm run release` 负责版本一致性、类型/边界检查、核心行为测试、依赖与资源审计、静态托管构建、
单文件构建、外部资源扫描、说明文件和 zip。所有临时产物成功后才替换已有发布目录，任何中途
失败都保留上一版可用产物。

发布前还必须完成本次改动涉及的实机冒烟项。发布命令通过不代表 Canvas 视觉自动通过。

## 4. 变更矩阵

`npm run qa` 始终执行；下表定义追加门禁。

| 变更领域 | 追加验证 | 通过标准 |
|---|---|---|
| `src/core`、战斗数据、羁绊、装备 | `npm run balance -- matrix`；定向改动再跑 `npm run balance -- ab` | 无死锁；强度与先手偏差在设计包络内 |
| 装备数值与合成 | `npm run balance -- items` | 成品正收益、合成正收益、协同不过界 |
| 整局经济、AI、局长 | `npm run balance -- match` | 对局结束；局长与原型差异在设计包络内 |
| 存档、结算、场景切换 | 对应核心测试（含本回合配对往返）+ 浏览器刷新/继续对局冒烟 | 不重复结算、不重掷本轮对手，不丢回合或玩家资产 |
| 器匣、装备栏交互 | 对应核心测试（溢出分页映射）+ 器匣点选/拖拽/翻页冒烟 | 溢出资产逐件可点选、可拖拽、可合成；页码不越界 |
| `src/render`、`src/ui`、布局、字体 | `../.qa/smoke-checklist.md` | 目标分辨率与 K=2 下无裁切、遮挡、错位 |
| 音频文件、清单、授权 | `npm run audit:music` + 开关往返冒烟 | 文件/哈希/授权一致；关闭时合成音回落 |
| 发布脚本、Vite 配置、资源路径 | `npm run release` | 两种产物可生成；单文件无外链；zip 完整 |

平衡命令以 `npm run balance -- <command>` 为唯一入口；`package.json` 中的 `sim:*` 仅是等价别名，文档与 CI 一律写 canonical 形式。同时影响多个领域时取验证集合的并集，不因改动规模小而省略对应门禁。

## 5. 核心测试策略

默认套件保持精简，聚焦六类项目风险：

| 风险 | 测试文件 | 保护内容 |
|---|---|---|
| 战斗可信 | `determinism`、`battle-formula`、`grid`、`skills`、`traits-big`、`status-src` | 收敛、重演、战斗规则、占格、技能与大羁绊、叠层按源分计（外来层不挤占 maxStacks）与非法状态数值入表前即抛、治疗记账单计与技能暴击单骰（拆分段共享判定）、装备击杀钩子端到端打标 |
| 平衡锚点 | `balance`、`shop-odds` | 定档数值回归（CRN 断面关键锚）、商店概率表结构与 rollShop 行为契约 |
| 工具链可信 | `balance-tools` | 平衡工具链自身：补丁四类路径往返与嵌套键级回退、CRN 配对公式金锁、进程池与串行逐位一致、SQLite 往返、**调参键白名单与 traits.ts 读取双向同源**、src 不引用工具链 |
| 资产正确 | `economy`、`conservation`、`adventure`、`round-flow`、`legend-qol`、`items-matrix`、`champions-integrity` | 收入、卡池（卖价公式绝对值钉死 + 2★/3★ 卖出回池数）、装备、奇遇六类、对局节奏与引导轮、天命与卸载、36 配方完备性与装备钩子行为、棋子表身份守卫（剪影×色相全表唯一、id 与中文名唯一） |
| 进度连续 | `save`、`match-resume`、`replay`、`undo`、`daily`、`status-src` | 存读档、恢复推进、回放、撤销（含随机流游标回滚与奇遇恩赐对称回写）、每日成绩、坏档单元清洗（丢弃/钳制/剥离，含装备超限截断、墨兽标记剥离、iid 重号去重、超长回池、恩赐验型，覆盖墨影快照与墨兽阵容）与配对兜底重掷不双记交手史、墨影空快照配对整表弃用 |
| 交互安全 | `hud-layout`、`input-coords`、`valid-placements`、`item-paging`、`robustness` | 单源几何（轨/日志/战报/弹窗/商店无重叠）、K=2 输入、拖拽落点合法域、器匣溢出分页的页数/钳制/绝对索引映射、满盘站位、坏输入与墨兽落地、moveToSlot 非整数槽位守卫、复活 spawn 在场账目与读档快照保留窗口、偏好写盘返回值 |

### 5.1 准入条件

新增测试必须同时满足：

- 失败能描述为一个具体项目故障，而不是“某函数返回值变化”；
- 现有场景不能自然覆盖该风险；
- 断言经过公开行为或稳定领域边界，不读取私有状态拼装实现；
- 输入确定、运行稳定、失败信息能直接定位受损规则。

### 5.2 排除项

以下内容不进入默认 Vitest 套件：

- 像素坐标、字号、文案换行、颜色和常量间距；
- 与实现同步变化的逐字段金快照；
- 休眠机制、实验参数和固定平衡数字；
- 已由发布脚本或资源审计完整覆盖的重复门禁；
- 为覆盖每个分支、每个 getter 或每个历史修复而拆出的形式化用例。

布局依赖真实渲染，平衡依赖统计模拟，授权资源依赖哈希审计。把这些问题写成普通单测只会制造
虚假的确定性。

`core/api`、`core/events`、`core/items`、`core/traits` 四个内核模块没有直接 import 的测试文件：
它们经 `Battle` 构建路径（技能/羁绊/装备闭环门、`status-src`、确定性重演）获得实质覆盖，
这是既定取舍而非缺口——为其拆出形式化的直接用例不满足 §5.1 准入条件。

## 6. 实机冒烟

Canvas、WebGL、音频上下文和真实指针事件必须在前台窗口验证。统一清单位于
`../.qa/smoke-checklist.md`，最低覆盖：

- 新对局、继续对局、每日挑战和图鉴往返；
- 买入、拖拽上场、出售、装备、卸载、开战与结算；
- K=1 与 K=2 输入对照；
- HUD、商肆底栏、计分板、羁绊笺和棋子头顶栈无遮挡；
- 典藏音乐开关、合成音乐回落和后台恢复无音爆。

仅勾选真实执行过的项目，并记录日期与环境。常量计算或源码阅读不能替代实机结果。

## 7. 通过标准

日常交付必须满足：

- `npm run qa` 退出码为 0；
- 无跳过、聚焦、重试或不稳定测试；
- 改动领域对应的专项门禁通过；
- 工作区差异中没有临时日志、快照、构建目录和无关文件。

发布还必须满足：

- `npm run release` 完整通过；
- 版本号与 CHANGELOG 一致；
- 相关实机冒烟完成；
- 发布包使用说明、授权清单和双形态产物齐全。

## 8. 失败处理

1. 先按层级确认失败属于类型、行为、构建、领域专项还是环境。
2. 能稳定复现的失败先修产品或测试边界，不降低断言以迁就未知结果。
3. 不稳定测试视为缺陷；修正数据、时钟或随机源，不使用自动重试隐藏。
4. 有意的平衡变化通过模拟更新设计结论，不更新金快照制造“通过”。
5. 环境阻塞必须在交付说明中列出命令、错误位置和未完成的验收范围。

架构决策见 [`adr/0001-risk-based-qa.md`](./adr/0001-risk-based-qa.md)。
