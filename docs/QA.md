# 百战天元 · QA 质量手册

本文档定义本项目的质量标准与验证方式：**不变量 → 测试 → 模拟 → 度量** 四层防线，
每一条都给出复现命令。所有数字均由可复现的脚本或浏览器内探针采集，不是估计值；
质量不是一次性的验收动作，而是任何人改完代码后都能在两分钟内重跑的固定流程。

## 0. 验证环境

| 项 | 值 |
|---|---|
| 运行时 | Node ≥ 20，Phaser 3.80，Vite 5，Vitest 2 |
| 类型检查 | `tsc --noEmit`，strict 全开，零错误 |
| 设计分辨率 | 1920 × 1080（Phaser `Scale.FIT` + `CENTER_BOTH`） |
| 战斗内核 | 30 Hz 固定步长，mulberry32 单一随机源 |
| 平台 | 桌面 Chrome / Edge（WebGL 优先） |

## 1. 快速验证回路（改完代码必跑）

```
npm run typecheck   # 类型层
npm test            # 300 项回归（~15s）
npm run build       # 生产构建（含类型检查）
```

平衡相关改动另跑：`npm run sim`（流派矩阵）、`npm run sim:items`（装备）、
按需 `sim:sweep` / `sim:ab`（方法论见 DESIGN §十一）。

## 2. 不变量（测试盯着的契约）

### 2.1 确定性

- 同 seed + 同输入 ⇒ **事件流逐字节一致**（JSON 逐条比对）；
- 不同 seed ⇒ 结果必须分歧（证明随机源真的在起作用）；
- 内核（`core/` `game/` `data/`）不存在 `Math.random()`，唯一随机源是注入的 mulberry32。

### 2.2 资源守恒

任何操作路径下，棋子与装备不凭空产生或消失：

- 共享卡池：买入 −1、卖出 +1、三星合成 −3（消耗三张）；
- 卡池跨版本守卫：恢复载荷含未知棋子 id / 负数 / 非整数计数 → 整池重置回满池
  （与新开局同基线），不凭空造卡不消卡；
- 装备：合成进器匣、卖出含装备的棋子返还全部组件、墨兽轮掉落守恒；
- 自动整理 / 买卖回滚 / 整局模拟路径全部有专项断言。

### 2.3 战斗公式口径

这是数值正确性的核心，每个口径一个测试：

- **暴击单结算**：普攻掷骰一次、`forceCrit` 传入结果，dealDamage 只乘一次倍率 ——
  否则暴伤变倍率平方、暴击率变 1−(1−p)²；
- **物理减伤**：`100/(100+护甲×(1−破甲))`，护甲/魔抗上限 220；
- **真伤口径**：无视抗性与通用减伤，易伤类增伤仍生效；DoT 的伤害类型随状态走
  （burn=法术、bleed 可为真伤），不按状态种类硬编码；
- **吸血语义**：普攻吃普攻吸血 + 全能吸血，技能/DoT/反伤只吃全能吸血；
- **超时裁定**：按剩余生命比例排序裁定，比例差 ≤2% 判平局；裁定与记录同口径
  **剔除召唤物**——一方冠军全灭仅召唤物存活直接判负，双方仅召唤物平局；
- **战斗输入校验**：重复 uid / 越界格 / 重叠格 / 非法星级在构造时抛错
  （与「未知棋子即抛」同契约），占位表与属性链路不可静默腐坏；
- **复活拒绝路径**：全盘满格时复活放弃（单位保持死亡），不覆盖他人占格 ——
  occ 占位表指向唯一化优先于个体复活；
- **天命单位（五费三星）**：数值按 `LEGEND_T3` 再乘、开战护盾、全能吸血、免疫控制
  （`CONTROL_KINDS` 全系拒绝）——普通三星与五费低星不触发（逐项有断言）；
- **同名上场**：同名棋子允许多张同场（`canPlace` 放行），羁绊按拥有唯一计数；
  人口上限规则不变；
- **装备钩子参数**：多件同钩装备聚合取最大值，聚合面与钩子实参同口径；

### 2.4 撤销与经济

- 撤销 = 完整玩家状态快照（含卡池计数），任意操作序列回退后逐字段一致；
- 异常路径（撤销栈中的非法操作）不破坏快照一致性；
- 利息 / 连胜连败 / 经验表与 `config.ts` 常量一致。

### 2.5 扫描框架自身

- 写入 → 战斗 → 还原：数值逐字段往返一致，中途抛异常也能还原；
- 非法路径（不存在的字段 / 非数字目标）必须抛错而不是静默；
- CRN：同种子同配置结果逐数字一致；参数覆盖确实改变战斗结果。

度量方法注记（曾引起误判的三个坑）：

- **内存泄漏判定看趋势不看单点**：40 次场景重启中出现过单轮 +167KB 的读数，
  跑满 40 轮后堆反而低于起始值 —— GC 噪声。结构性指标（显示列表 / 更新列表 /
  纹理数）持平才是判据。
- **WebGL canvas 读像素**必须开 `preserveDrawingBuffer` 或在 rAF 回调里读，
  否则拿回全黑 —— 曾差点误判生产构建白屏。
- **console 采集只抄不吞**：报错/警告抄一份到 ring buffer，原始 console 行为不变，
  "零报错"是对真实控制台说的。

## 5. 性能包络

### 5.1 战斗场景（22 单位同屏，1920×1080）

| 指标 | 值 |
|---|---|
| 帧间隔均值 / P95 / 最大 | 6.6 / 7.5 / 8.0 ms |
| 超 16.7ms 的帧 | 0% |
| 解锁帧率上限后 | 181 FPS |
| 每帧实际工作耗时 | 4.67 ms（预算占用 28%） |

### 5.2 准备阶段（满编棋盘 + 满器匣）

| 指标 | 值 |
|---|---|
| 每帧工作耗时 | 6.44 ms |
| 解锁帧率 | 130.8 FPS |
| 实时 Graphics 指令 | ~9,700 条（棋盘格 / 备战席 / 棋子卡均已烘焙为纹理） |

性能纪律：**形态不随帧变化的图形一律烘焙**（`render/view/bake.ts`）。WebGL 的
`Graphics` 每帧重放整个命令缓冲，一个圆角矩形 ≈ 45 条命令 —— 棋盘格层
曾是 9,848 条指令独占 8.6ms/帧，烘焙后归零。

### 5.3 生产构建

| 项 | 值 |
|---|---|
| app 包 | ~98KB gzip（phaser 单独分包 ~340KB） |
| 页面加载 / 遮罩移除 / 实际渲染 | ✓（像素采样与开发版一致） |

## 9. 视觉验收

界面为 Canvas 程序化绘制，视觉验收 = 运行 `npm run dev` 后对以下要点过目：

- 准备场景：面板空态文案、朱印出售区、商店卡立绘与稀有度底色、无文字重叠/截断；
- 战斗场景：血条颜色（我方玉青恒色 / 敌方朱砂）、星级描边（2★银 / 3★金）、飘字与顶栏无重叠；
- 羁绊轨：徽章四态（灰 / 一圈金 / 两圈金 / 三圈金）可瞬辨，篆字居中环内、计数在环右；
- 清晰度：125%/150% 系统缩放与 200% DPR 下文字与棋子不发糊（DPR 底座生效）；
- **DPR 交互验收**：K=2 下买子拖上盘、拖出售印、装备两段流、
  悬停详情/提示卡贴指针、羁绊浮层与图鉴滚轮、音量滑杆逐项与 K=1 对照
  （场景级命中全走 screenToWorld 咽喉，纯函数几何由 input-coords.test 钉死）；
- 色相纪律：全项目禁用高饱和荧光色（蓝/绿/紫），规范见 ART_BIBLE §2.6；
- 三星五费全屏演出「天命之印」完整播放。

## 10. 已知限制

见 **[DESIGN.md §十三](./DESIGN.md)** —— 局长、极端克制边机制、
