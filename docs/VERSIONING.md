# 版本迭代规范

本文档定义项目的版本编号、锁版状态、正式发布与回退。日常开发与提交规则见
[DEVELOPMENT.md](./DEVELOPMENT.md)。

## 1. 版本编号

遵循[语义化版本](https://semver.org/lang/zh-CN/)：`主.次.修订`（如 1.6.0）。

| 位 | 何时递增 | 典型内容 |
|---|---|---|
| 主版本 | 玩家存档不兼容的破坏性变更（存档结构废弃、玩法重置） | 预留 |
| 次版本 | 新功能、新内容（棋子/羁绊/装备/场景）、可见的体验改动、平衡断面移动 | 新场景、64 棋子扩军、典藏音乐 |
| 修订版 | 纯修复（正确性 / 资源生命周期 / 崩溃）、文档与工具链，不改可见行为 | 坐标修复、泄漏清扫 |

判定口诀：**玩家能看见或能玩到差异 → 次版本；只有坏的东西变好了 → 修订版**。
一次迭代同时含功能与修复时，按最高位计（功能 + 修复 = 次版本）。

## 2. 锁版状态

版本有两个机器数据源和一份发布记录：

| 位置 | 字段 | 消费方 |
|---|---|---|
| `src/version.ts` | `GAME_VERSION` / `GAME_BUILD` | 主菜单落款 |
| `package.json` | `version` | 发布脚本（zip 命名、使用说明） |
| `docs/CHANGELOG.md` | 顶部条目 | 人类可读的发布历史 |

`npm run release` 在构建前自动校验前两者的字面一致，避免界面与压缩包错版；发布者同时确认
CHANGELOG 顶部条目记录相同版本。只有三者齐备才是锁版状态，不宣称脚本自动理解发布文案。

## 3. 发布流程

```
npm run qa               # 1. 类型 + 边界 + 核心行为 + 生产构建
npm run release          # 2. 重跑关键门禁 + 依赖/资源审计 + 双形态构建 + 产物体检
```

发布纪律：

1. 功能与修复可以由多个原子提交组成；正式发布使用一条 `chore: release vX.Y.Z` 锁版提交，
   统一版本号、CHANGELOG 与发布说明。
2. **确定性回归**：任何影响战斗内核的改动（`core/`、`data/`、涉及 rng 消费顺序的
   `game/` 改动）落地后跑 `npm test`，确认真实阵容同 seed 可重演；不维护会随正常
   平衡调整整体漂移的逐字段金快照。
3. **平衡断面**：改了 `data/` 数值或超时/裁定口径，必须重跑 `npm run sim` 并把
   新极差/先手写回 DESIGN §十二（README 不承载平衡断面，真源唯一在 DESIGN）。
4. **文档同步先于锁版**：CHANGELOG 新条目与本次变化涉及的设计、操作、视觉或发布真源
   一次改齐，不把实时测试数和包体复制到多个活文档。
5. `npm run release -- --skip-typecheck` 是并行线未收敛时的逃生门：跳过整仓类型检查
   （产物走 esbuild 打包），单测与资源审计照跑。仅限发布线与在途改动确需物理隔离时
   使用，正常发布不得携带该参数。
6. 产物通过后创建 annotated tag `vX.Y.Z` 并推送；已发布标签不得移动或强推覆盖。
7. 将 zip 与授权清单保存到对应 GitHub Release 或外部版本化存储，不能依赖被忽略的本地
   `release/` 目录承担历史归档。

## 4. CHANGELOG 条目规范

- 采用 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 分节：
  新增 / 变更 / 修复 / 移除；顶部条目 = 当前版本。
- 标题行：`## [x.y.z] - 日期 · 一句话主题`。
- 条目写**行为与口径**，不写"修了 XX 问题"的过程叙事（补丁式口吻禁止）：
  每条自含完整语义，读者不需要知道上一次迭代的历史即可理解当前规则。
- 数字（胜率、包体、测试数）随条目落定，作为该版本的存证。

## 5. 文档真源与同步责任

| 变更面 | 必须同步的文档 |
|---|---|
| 版本号 | `src/version.ts` + `package.json` + CHANGELOG 顶部 |
| 测试策略/风险覆盖 | QA.md §5 |
| 数值与平衡 | DESIGN §十二 |
| 视觉/布局规格 | ART_BIBLE（代码镜像：`palette.ts` / `kit.ts`） |
| 操作/打包/产物 | README 对应节 |
| 发布流程变更 | 本文（VERSIONING.md） |

## 6. 回退

正式分发后发现启动失败、存档或资产损坏、确定性破坏、授权缺失时，停止继续分发并恢复上一
标签对应的已验证产物。没有归档时，在干净临时工作区检出上一标签，执行 `npm ci` 和完整发布链
重建。修复使用新的修订版本，不删除历史提交，不移动既有标签。

## 7. 遗留约定

- `0.x` 阶段（M2 之前）以里程碑代号（0/F/R/M1）归档于 UPGRADE.md，
  `1.0.0` 起进入语义化版本，历史见 CHANGELOG。
- 未发布的中间状态不占版本号：开发分支上的改动统一并入下一次版本 commit。
- 存档兼容性：`save.ts` 内部带载荷版本（v2→v3 迁移先例）；次版本迭代必须保证
  旧档可读（迁移或回退），主版本才允许弃档。
